# Architecture

The `~/.agent-team` directory (on WSL, the Linux side) owns portable rules, role descriptions, skills and shared memory. Claude loads its global CLAUDE.md and Markdown agents; Codex loads its global AGENTS.md and standalone TOML agents. Discovery directories link to personal skills in WSL and hold snapshots in Windows. `agent-team sync` reconciles WSL-owned content to Windows; mutable native Windows memory must be reconciled before sync.

`team.py` supplies CLI launchers, worktree creation, pane spawning and messaging, and a local review-record push helper.

## Pane teams (issue #3)

- **Boundary:** each agent is one CLI process in one tmux pane. There is no in-process subagent layer for team roles; read-only in-process search helpers are the only exception. The launcher (`claude-team`/`codex-team`) owns provider identity, `spawn` owns pane lifecycle, and the file mailbox owns messaging. Dependency direction: launcher -> spawn -> mailbox; roles, skills and prompts carry no code dependency on `team.py`.
- **Provider identity:** the launcher stores `@agent_team_provider` (claude|codex) as a tmux session option and exports `AGENT_TEAM_PROVIDER/SESSION/ROLE/STATE/CHIEF_PANE`. `spawn` refuses a different provider, so a team never mixes providers. Chief's prompt is `bootstrap-<provider>.txt` rendered by replacing only `{{PROVIDER}} {{CHIEF_MODEL}} {{VALIDATOR_MODEL}} {{WORKER_MODEL}} {{EFFORT}}` from `models.json`; the Claude prompt never names Codex models and vice versa. A missing bootstrap file is a clear error, not a fallback.
- **Layout:** panes are split into Chief's window and titled `role` or `role:task`, then the layout is re-tiled, again when a pane exits. At `AGENT_TEAM_MAX_PANES` (default 6) or "no space for new pane", `spawn` opens a new window in the same session.
- **Messaging:** `send` writes `mailbox/<role>/<UTC stamp>-from-<sender>.md` under `$AGENT_TEAM_STATE`, then posts a one-line `[from X] read <path>` notice, typed only if the target pane's input line is empty (last prompt line has nothing after the marker; checked for every pane, always for Chief, whose input line belongs to the user). Otherwise or if undeterminable it shows `tmux display-message` and retries injection for about 60s, then gives up silently; Chief also watches its mailbox. The file is always the durable record; `inbox` prints and archives unread files to `read/`. The file is the source of truth, so a lost notice or dead pane loses no message. A pane registry (`panes.json`, written atomically) records role, task, pane, window, cwd, provider, model and start time.
- **Authority:** Chief is the only agent that talks to the user. Validator and workers report to Chief, deliver one assigned increment, and start no autonomous loops. Chief delivers one user-testable increment at a time and waits for the user's go-ahead before the next.
- **Startup handshake:** Validator sends Chief an acknowledgement (role, model, effort, pwd) on startup; Chief waits at most about 5 minutes, then reports degraded mode to the user. The setup no longer enables Claude's experimental in-process agent teams (the `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` env flag and `teammateMode`), since they produced in-process teammates; `CLAUDE_CODE_SUBAGENT_MODEL` stays for read-only helpers, and stale keys in an existing `settings.json` are removed at deploy time, not by `build_setup.py`.
- **Failure modes:** not in tmux or no recorded provider -> `spawn` errors; duplicate live (role, task) -> refused; Claude workspace-trust prompt -> auto-accepted only for a git worktree whose main checkout is already trusted, else reported as `awaiting_trust`; Validator unavailable -> Chief reports degraded mode and gated delivery stops.
- **Versioning:** the bootstrap token set and CLI surface above are the contract. Changing a token name or a `spawn`/`send`/`inbox` flag is a breaking change to the prompts and role text, which are updated together (`build_setup.py` seeds and the `team/` snapshots must stay identical).
- **Revisit when** the provider CLIs offer a supported programmatic attach/message API that makes panes unnecessary, or when more than about two windows of agents are routinely needed.

Separate provider teams do not share a messaging bus; they exchange durable handoff files with agreed ownership.

Worktrees are siblings of the project checkout. Review approvals are stored under the Git common directory, keyed by exact SHA, with hashes of evidence reports. The push helper verifies clean state, two approvals and unchanged reports, rejects default branches and pushes the reviewed object ID. This helper does not intercept arbitrary Git commands and does not authenticate reviewer identity cryptographically.

On WSL, Windows PowerShell profile functions retain native CLI use for regular `claude`/`codex` and route team commands to Ubuntu. WSL executable resolution uses installed Linux vendor paths and supplies Node's PATH for non-login shells. Explicit safer permission flags suppress bypass injection; CLI settings remain subject to project and organization policy.

Install scripts preserve existing settings/hooks and keep backups outside this repository. ECC is installed via native plugin lifecycles. CCPM is a discoverable skill with bundled references. Hermes and Herdr are optional separate tools and are not installed by this setup.

## One-prompt install (issue #5)

- **Boundary:** `install.sh` (and `install.ps1` on Windows) is the only entry point. It owns OS/package-manager detection, prerequisite checks, backups, copying `team/` to `<home>/.agent-team`, and invoking the two deployers (`build_setup.py`, `install_launchers.py`). Dependency direction: `install.sh` -> deployers -> `team.py` helpers; `agent-team doctor` (in `team.py`) is read-only and depends on nothing the installer does not also produce. Root `CLAUDE.md` / `AGENTS.md` are agent-facing runbooks that only call the CLI surface below; they carry no logic.
- **Contract:** `./install.sh [--dry-run] [--yes] [--no-system] [--home DIR] [--windows-home DIR|--no-windows] [--restore TIMESTAMP] [--yolo]`. `--home` redirects every write under `DIR` (and the given Windows home), which is how tests run in throwaway homes with fake tool binaries. `agent-team doctor [--json]` exits non-zero on any failure and prints the exact fix command per row. Adding or renaming a flag or doctor row is a breaking change to the runbook and tests; update them together.
- **Opt-in YOLO and rules:** permission-bypass defaults are enabled only with `--yolo`; the runbook asks once, together with the sudo confirmation. Global rules are a managed block (BEGIN/END markers) inside the user's `CLAUDE.md` / `AGENTS.md`; content outside the block is never modified and re-runs replace only the block.
- **Paths:** no user-specific absolute paths in shipped files. `HOME` comes from the environment or `--home`; the Windows profile from `cmd.exe /c echo %USERPROFILE%` plus `wslpath` (override `AGENT_TEAM_WINDOWS_HOME`); non-WSL hosts get no Windows sync. Launchers embed only the install root resolved at install time.
- **Idempotency and rollback:** unchanged files are skipped, so a second run is a no-op; every changed file is copied to `<home>/.agent-team/backups/<timestamp>/` first; `--restore` replays that backup. Memory templates are seeded only when absent so learned content is never overwritten.
- **Portability:** bash 3.2 and BSD tools (macOS); apt, dnf, pacman and Homebrew detected, others print manual steps.
- **Failure modes:** missing prerequisite or declined sudo -> continue with `--no-system` semantics and list what is missing; missing/unauthenticated `claude`/`codex` -> plugins skipped and flagged by `doctor` with the command; unknown OS -> print manual steps, change nothing. Logins are never automated and credentials are never read.
- **Public-repo constraint:** tracked files contain no personal names, absolute home paths, emails, tokens or machine details; tests scan `git ls-files` for them.
- **Revisit when** a provider ships a first-party installer for global rules/agents/skills that makes `build_setup.py` unnecessary, or Windows-native team sessions (without WSL) become supported.
