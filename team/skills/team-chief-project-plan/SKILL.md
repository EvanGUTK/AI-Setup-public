# Chief — Orchestrator: Project Plan

## Inputs
Approved task and acceptance criteria, relevant repository files, current role/worktree, and applicable user preferences. Read the relevant role definition when ownership is unclear.

## Procedure
Specify journeys, non-goals, alternatives, architecture, tree, milestones, dependency graph, acceptance criteria, budget and rollback. Present concrete decisions for approval. Split the plan into user-testable increments, each stating what changes, how the user tests it and the demo URL or stop steps, and name which increment is next. Autonomy applies only inside the approved increment.

## Evidence and output
Approved plan with ordered user-testable increments and unresolved decisions recorded.
Provide concrete file or command references and distinguish observed outcomes from assumptions. Validate at the smallest meaningful layer; do not claim checks that were not run.

## Failure handling
Report missing inputs or failed checks to Chief with evidence and the next recoverable action. Do not bypass Validator, broaden scope, or invent successful results.
